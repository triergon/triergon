# D2 selected additive source contracts

This batch preserves every original source/text/carriage test, all177 original native captures, the104 default-carriage versus73 decoder/charset-diagnostic memberships, and the existing native selector/worker/reference flags. Existing default source behavior remains for every original enum/profile input. Source bytes, configuration/charset labels and epochs, raw/exact clocks, physical ranges, opaque additions and held owners remain independent from derived UTF-8 and native projections.

The new tx3g_iso_boxes constructor selects Tx3gIsoBox1 explicitly. The original constructor keeps its size0/size1 Unsupported results. The additive profile reads ordinary/extended/end-of-complete-sample boxes with checked geometry, UUID header minima, policy box caps, incremental headers and exact original ranges. Opaque modifier bodies remain opaque. No text length is clamped to imitate the consumer and no bytes are scanned, joined or rewritten to manufacture boundaries.

CharsetJob strictly converts an explicitly selected UTF8/UTF16/BOM, ASCII, ISO8859-1, Windows1251 or Windows1252 byte stream. UTF8 aliases only after complete validation; others count then encode into exact charged storage. Undefined legacy bytes are explicit errors, with no replacement, guessing or label-truth inference. The caller's source and even contradictory declared-label owner survive unchanged. Single-byte mapping DATA comes from pinned Microsoft/Unicode tables with the original Unicode licence; algorithms are original safe Rust. No external production package is added. All512 byte outcomes are independently checked with Python codecs at three work quanta.

Explicit Ascii/Latin1/Windows1251/Windows1252 Encoding variants also enter SubRip source extraction. They reuse the forward source cursor and framing so UTF8 output remains separate from original single-byte physical ranges. Charset selection/detection is never inferred from a language or byte guess. WebVTT and Utf8Packet retain their UTF8 requirements; Opaque retains its old behavior. Undefined bytes are rejected during whole-input validation, before any apparently valid prefix event.

ConfigJob extracts an explicitly identified full SampleEntry body or30-byte defaults-record prefix. It never assumes arbitrary AVCodec extradata or a whole ISO box has either layout. Fixed source flags, signed justification/geometry, RGBA and style bytes remain exact. The full layout preserves its data-reference index; the shorter layout explicitly has no such source field. Required font tables are parsed into charged ordered ID/name ranges with strict UTF8 names and finite counts; unknown child boxes remain original ranges. Absence does not become default font/style/geometry. This is source extraction, not inherited rendering, font fallback or automatic mutation of Input.codec_private/configuration_epoch.

New jobs clone checked same-pool source owners; constructor rejection leaves caller owners intact. All loops are paid before bounded byte/scalar/record work. Zero-work calls yield without new storage/progress. Allocation/retained-output pressure keeps completed headers/scalars pending. Charset and configuration cancellation is resumable, consistent with the existing text source contract; dropping a job releases construction. Fatal errors are sticky and cannot publish a repaired empty object. This differs explicitly from PGS's sticky cancellation policy, which this batch does not change.

The explicit Windows1251 native observation contains an exact32-byte ASS payload and then an original -22 observer/operation stop. The new converter agrees with the full payload while that complete native error/process history stays intact. It is not promoted to a clean full native decoder pass. Decoder diagnostics do not replace the original bypass-carriage operation or its complete ordered guards.

Remaining required work: other legacy charsets and complete native qualification of the explicitly named multibyte profiles, any future detector/track-policy integration, tx3g modifier semantics and precedence, disparity/renderer behavior, complete container/configuration-to-consumer integration, and full native operation/numerical/target qualification. Existing consumer charset/detector code remains consumer-owned; replacing it is not newly imposed as a prerequisite on the frozen bypass contract. No D4, DVD, Streem, public tree, reference option, performance or numerical-gate change is made.

The additive [multibyte contract](MULTIBYTE-CONTRACT.md) now defines independently
authored strict GBK, historical Big5/Shift-JIS, EUC-KR and distinct Windows932/949/950
profiles, including explicit SubRip ingestion. The original resolver/defaults,
source identities and native history stay unchanged. This adds source conversion;
remaining other charsets, full native compatibility, numerical qualification and
tx3g modifier semantics remain required. The new source is not tested by the old batch's receipts.
