# Capture comparison

The capture pipeline (`crates/capture`: RGBA to YUV 4:2:0, MPEG-1 video, MPEG-TS) is
compared with FFmpeg 9.0.2 under the rules of `contract.json`, on the cases of
`cases.json`, on native Linux.

```sh
cargo xtask prepare-ffmpeg --profile capture        # gating reference build
cargo xtask prepare-ffmpeg --profile capture-small  # the same with --enable-small
cargo xtask prepare-ffmpeg --profile decode         # independent ffmpeg and ffprobe
cargo xtask build-workers
TRIERGON_PYTHON=python3 cargo xtask capture qualify \
  --candidate target/release/capture-worker \
  --reference target/harness/ffmpeg-capture-worker \
  --reference-small target/harness/ffmpeg-capture-small-worker \
  --oracle-bin .research/reference-decode/install/bin \
  --observer target/harness/allocations.so --inputs DIR --out DIR
cargo xtask capture summarize DIR
```

The comparison runs on native Linux AArch64 and in the 32-bit ARMv7 user space
([quality](../../docs/quality.md#32-bit-armv7)), each with its own reference build.
The reference's conversion follows its target, and the converter follows the ARMv7
build: the contract's `open_cases` list the AArch64 build's conversion of all 15
cases. `qualify` still compares and reports them as failing and marks them
`open_on_target`. It refuses a listed id that is not in the cases file, and fails
once every case is measured if a listed case passes.

The gate times and measures memory in separate runs: the same command with
`--stage timing --out TIMING` under `taskset -c 1`, then with `--stage memory --timing
TIMING --out DIR`, which collects every case's memory in parallel on the CPUs it may
use, each case from its own copy of its generated input under `--inputs`, removed when
the run ends.

Inputs are generated by `generate_inputs.py` (numpy; see its header).
`target/harness/identity.json` records each worker and reference build.

The memory gate requires native Linux on AArch64 or 32-bit ARMv7, at least 30
pairs, and a calibrated observer that covers both workers. Each observation must reproduce the byte count
and digest from its worker's correctness run. The report grades peak live heap and
total resident peak RSS. It also reports resident growth as a diagnostic.

## Short frames

The conversion probe checks every luma and chroma sample at the seven even
widths below 16, in both row orientations, at heights 2, 4 and 6. Each size and
orientation uses a red impulse in each source row and 32 pseudo-random pictures.
The AArch64 Linux probe also checks widths 18, 22, 34, 66, 258, 958 and 4094,
where the converter uses the filtered fallback. Both probes require exact
sample equality. The AArch64 resolution probe also checks one 480×270 and one
960×540 picture in both row orientations. Its parameter recovery test uses
two-row frames to recover the chroma coefficients and six-row frames to
recover the first vertical filter row. Build the capture reference for the
target as above and give the tests a fresh output directory.

```sh
CAPTURE_REFERENCE="$PWD/target/harness/ffmpeg-capture-worker" \
CAPTURE_PROBE_DIR="$PWD/.research/short-capture" \
CARGO_INCREMENTAL=0 cargo test --release -p capture-worker --test short_chroma -- --ignored
```
