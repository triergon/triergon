# Capture comparison

The capture pipeline (`crates/capture`: RGBA to YUV 4:2:0, MPEG-1 video, MPEG-TS) is
compared with FFmpeg 9.0.2 under the rules of `contract.json`, on the cases of
`cases.json`, on native Linux.

```sh
cargo xtask prepare-ffmpeg --profile capture        # gating reference build
cargo xtask prepare-ffmpeg --profile capture-small  # the same with --enable-small
cargo xtask prepare-ffmpeg --profile decode         # independent ffmpeg and ffprobe
cargo xtask build-workers
TRIERGON_PYTHON=python3 cargo xtask capture qualify \
  --candidate target/release/capture-worker \
  --reference target/harness/ffmpeg-capture-worker \
  --reference-small target/harness/ffmpeg-capture-small-worker \
  --oracle-bin .research/reference-decode/install/bin \
  --observer target/harness/allocations.so --inputs DIR --out DIR
cargo xtask capture summarize DIR
```

The gate times and measures memory in separate runs: the same command with
`--stage timing --out TIMING` under `taskset -c 1`, then with `--stage memory --timing
TIMING --out DIR`, which collects every case's memory in parallel on the CPUs it may
use, each case from its own copy of its generated input under `--inputs`, removed when
the run ends.

Inputs are generated by `generate_inputs.py` (numpy; see its header).
`target/harness/identity.json` records each worker and reference build.

The memory gate requires native AArch64 Linux, at least 30 pairs, and a calibrated
observer that covers both workers. Each observation must reproduce the byte count
and digest from its worker's correctness run. The report grades peak live heap and
total resident peak RSS. It also reports resident growth as a diagnostic.
